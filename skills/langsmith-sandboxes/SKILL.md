# LangSmith Sandboxes Skill

This skill provides instructions on how to use LangSmith Sandboxes to safely execute untrusted, agent-generated code. It is designed to overcome the security limitations of standard Docker containers by providing hardware-virtualized microVMs.

## Overview

When building AI agents that write and execute code (e.g., coding assistants, data analysts, CI agents), running that code on the host machine or in a standard Docker container is a security risk. Docker containers share the host kernel, leaving them vulnerable to kernel exploits (like CVE-2026-31431) and supply chain attacks (like the Shai-Hulud npm worm).

LangSmith Sandboxes solve this by providing each agent with its own hardware-virtualized microVM. Each sandbox has:
- Its own kernel
- A filesystem and shell
- A package manager
- Network access
- Persistent state across the session

## When to Use LangSmith Sandboxes

Use this skill when your agent needs to:
- Generate and verify code execution before responding.
- Operate on real files (e.g., cloning repos, data pipelines).
- Run multi-step workflows where state must persist across tool calls.
- Execute any user-supplied or model-generated input.
- Spin up isolated environments at burst scale (e.g., for RL training or evals).

Do NOT use this for:
- Agents that only call predefined APIs with fixed schemas.
- Retrieval agents that just search docs and return citations.

## Implementation Pattern

To integrate LangSmith Sandboxes, use the `langsmith` Python SDK.

### 1. Basic Setup

```python
from langsmith import Client

# Initialize the LangSmith client
client = Client()

# Create a new, isolated sandbox
sandbox = client.create_sandbox()

# Execute code within the sandbox
result = sandbox.run("pip install pandas && python analysis.py")

# Access the output
print(result.stdout)
```

## Advanced Features

LangSmith Sandboxes support several advanced primitives that you should leverage for production readiness:

- **Snapshots and Forks**: Capture a sandbox mid-session and boot new ones from it using copy-on-write. This allows parallel branching (e.g., trying multiple paths) without rebuilding from scratch.
- **Blueprints**: Define a base image (e.g., cloned repo, installed dependencies) to boot pre-warmed sandboxes in seconds.
- **Service URLs**: If the agent starts a local web server in the sandbox, it automatically generates an authenticated URL to share or preview without manual port forwarding.
- **Auth Proxy**: Outbound network requests flow through a proxy that injects credentials, ensuring secrets never touch the agent's runtime.

## CRITICAL Security and Architecture Constraints

- **Never Use Docker for Untrusted Code:** A container boundary is not an isolation boundary. Always use the hardware-virtualized LangSmith Sandboxes when executing code generated by an LLM or provided by a user.
- **Isolate Secrets:** Never pass raw API keys or secrets directly into the sandbox runtime. Always rely on the built-in Auth Proxy to inject credentials at the network layer.
- **Treat Sandboxes as Ephemeral:** Assume the sandbox will disappear when the work is done. Extract any necessary artifacts or results before the session ends.
